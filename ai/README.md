# Funding Radar ChatGPT skill

This portable skill teaches ChatGPT to discover and explain potentially relevant funding opportunities for Portuguese local authorities and organisations using Funding Radar’s public, versioned static API.

It does not bundle catalogue or opportunity data. The API remains the current dataset and is periodically regenerated by the Funding Radar site build. Consumer questions use the user’s ChatGPT inference/context; Funding Radar does not make an inference call, run a chatbot, or pay an additional LLM cost for those questions.

## Files

- `SKILL.md` — the skill instructions.
- `evals.md` — realistic prompts and observable expected behaviour.

## API used

Base: `https://radar-de-financiamento.decidimosarroios.pt`

- `/api/v1/meta.json`
- `/api/v1/catalog.json`
- `/api/v1/schema.json`
- `/api/v1/opportunities/{id}.json`

The catalogue is a discovery index of open or unknown-status opportunities. Detailed records may also contain retained closed opportunities. Details separate source-oriented `facts`, Funding Radar `analysis`, `provenance`, and authoritative `links`; see `SKILL.md` for the interpretation rules.

## Current skill format and import

This follows the currently documented ChatGPT skill model: a skill is an uploadable package of instructions and optional supporting resources, with `SKILL.md` as the entrypoint. No undocumented manifest or plugin metadata is included.

For an eligible ChatGPT workspace, make a ZIP containing the `funding-radar/` directory (with `SKILL.md`, this README, and `evals.md`), then:

1. Open ChatGPT’s sidebar **Plugins** and the **Skills** tab.
2. Choose **Create** → **Upload from your computer**.
3. Select the ZIP/package, review the scan, and install it.
4. Start a new conversation and ask one of the prompts in `evals.md`; confirm that the skill is enabled/available if the surface provides that control.

The exact menu and eligibility depend on the ChatGPT account and workspace. OpenAI’s current documentation says Skills are available to eligible Business, Enterprise, Healthcare, and Edu users, subject to workspace settings. It also documents creating via chat/editor and installing skills shared with a workspace. If the UI accepts a skill folder or `SKILL.md` directly, use the same contents without changing the files.

## Can ChatGPT fetch the API directly?

The skill contains URLs and instructs ChatGPT to retrieve them, but `SKILL.md` does not itself grant an HTTP tool. Direct retrieval is expected only when the importing ChatGPT surface has web/browsing access that can open public JSON URLs. The current skill documentation confirms uploadable instructions/resources, but does not guarantee arbitrary public HTTP retrieval for every ChatGPT surface or plan. Test this after import. If retrieval is unavailable, the static-API-only experiment cannot produce current catalogue-based answers in that surface; paste the JSON or use a web-enabled surface. Do not build a proxy, MCP server, action, or backend as part of this experiment.

## Testing

Run the prompts in `evals.md` manually in the imported skill. Check that ChatGPT:

- retrieves metadata and reports freshness;
- uses semantic discovery and a small shortlist;
- fetches detail records;
- does not turn unknown eligibility or geography into positive claims;
- handles closed, imminent, and unknown deadlines;
- separates Funding Radar analysis from official facts;
- links authoritative sources and responds in the user’s language.

For repository validation, inspect the source contract and build the site with the project commands:

```sh
bundle exec rake test
npm run build:css
npm run build:js
bundle exec jekyll build
```

After the build, inspect `_site/api/v1/meta.json`, `_site/api/v1/catalog.json`, `_site/api/v1/schema.json`, and representative `_site/api/v1/opportunities/{id}.json` files. The live API, not bundled skill files, is authoritative.

## Future Plugin Directory release

This is not a Plugin Directory plugin and intentionally has no MCP server, app connection, OAuth, API key, action, dynamic endpoint, database, or inference backend. A future public plugin release would require following the then-current OpenAI publishing/review requirements and, if external service integration were needed, a documented app/action/plugin manifest and service security/privacy review. None is required for this static skill experiment.
